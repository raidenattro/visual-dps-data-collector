# 2026-08-03 多人区间标真与配色稳定性修复

## 问题

- 单帧已经支持人物 A/B 分别绑定货框，但区间模板、确认弹窗和请求仍只携带当前人物的一组 `confirmed + personId`。
- 修改某个人物货框时，旧实现会把该人物 binding 删除后追加到数组末尾；稳定身份信息短暂不可用时，备用颜色按数组顺序分配，可能造成紫色/橙色偶发交换。

## 修改

- 区间首帧快照冻结完整多人 `bindings`，不再只冻结当前人物。
- 人物 A/B 在区间内分别执行相邻帧空间连续性跟踪，每帧写入真实 raw `person_id` 与各自货框。
- 每个稳定人物使用独立的低置信度人工确认锚点；两个人被错误映射到同一个 raw person_id 时停止整段保存并要求确认。
- 区间提示与确认弹窗显示“人物 → 货框”完整配对，保存后逐帧校验所有 binding。
- 更新单个人物货框时原位替换 binding，保持 A/B 顺序和备用配色稳定。
- 配色优先使用稳定人物编号，临时取不到当前帧身份时再使用已建立的 track→稳定人物映射，最后才回退到 binding 顺序。

## 数据格式

```json
{
  "frame_idx": 21,
  "bindings": [
    {
      "person_id": 1,
      "person_track_id": "physical-person-a",
      "confirmed_box_tokens": ["Box_2011"]
    },
    {
      "person_id": 0,
      "person_track_id": "physical-person-b",
      "confirmed_box_tokens": ["Box_1012"]
    }
  ]
}
```

人物物理身份不依赖 raw P0/P1；上例表示下一帧发生 raw 编号交换，但两个人与各自货框的配对没有交换。

## 第一、第二批复核工作台优化

- 新增“单帧标注 / 区间标注”显式模式，`Tab` 切换；区间模式用橙色区分，`Esc` 清除区间草稿并返回单帧。
- A/D/R 只在区间模式生效，Y/U 只在单帧模式生效，页面同时显示本次操作影响的帧或区间。
- 右侧改为复核工作台：保存状态、失败重试、`Ctrl+Z` 撤销、身份异常上一处/下一处、专注模式和 F1 快捷键帮助集中显示。
- 单帧主操作吸附在工作台底部；区间入口固定在工作台上方，避免因滚动而找不到。
- 多人物配对以可移除彩色标签显示，解除单个人物—货框绑定时不影响其他人物。
- 切换事件不再清空未落盘的人物/货框草稿；切换记录、导入 JSON 或关闭页面前检测草稿并提示。
- 播放区域改为算法事件、人工复核结果双轨时间轴，并加入当前帧蓝色游标。
- 全部事件列表按每批 240 条渲染，支持上一批/下一批，降低长视频页面渲染开销。
- 增加“身份待确认”筛选和异常导航；多人且身份未落盘、区间待人工确认的帧会进入异常队列。

## 验证

- 9 组前端 Node 回归脚本通过，覆盖多人绑定、人物稳定编号、区间身份、播放导航和工作台交互。
- 26 组 Python `unittest` 通过，覆盖 schema v2 往返、并发写入、逐帧区间保存、多人独立 binding 与下游消费。
- 本地服务使用 CPU 模式在 `http://127.0.0.1:8767/` 启动并返回 HTTP 200。

# 2026-08-03（补丁）收窄「身份待确认」判定范围

## 问题

- 实机打开 868 帧记录时，状态条显示「身份待确认 868 处」，即全部事件都被判为待确认，等于没有判定。
- 连带后果：复核时间轴人工通道整条染成橙色，「已标真 / 未处理」的真实进度被淹没；侧栏常驻一条无信息量的告警条。
- 根因在 `eventNeedsIdentityAttention()` 的第二条判据 `ids.length >= 2 && getEventPersonId(ev) == null`：只要本帧有 ≥2 人且尚未选人就算异常。该视频全程两人、又尚未开始复核，故全量命中。这条判据表达的是「多人 + 未处理」，与既有的「未标真」队列完全重合。

## 修改

- `eventNeedsIdentityAttention()` 只保留 `isRangePersonConfirmationRequired()` 一条判据，即区间标真逐帧跟踪人物 A/B 时撞上低置信度身份切换点、必须由人裁决的情形。该分支是数据正确性保障（raw P0/P1 交换时防止静默配错），保持不变。
- `rangeAnnotAwaitingPersonFrame` 是单值，同一时刻最多一个待确认点，因此把「队列」语义降级为「单点」：
  - `getEventReviewAnomalies()` → `getEventReviewPendingIdentity()`，返回单个事件或 `null`。
  - 状态条无待确认时加 `hidden` 整条不渲染，出现时才以橙色告警样式弹出，文案改为「帧 N 身份待确认」+ 一句处理说明。
  - 「上一处 / 下一处」两个按钮合并为单个「跳转」按钮；同步移除 `[` / `]` 快捷键与 F1 帮助中的对应条目。
  - 队列下拉移除 `identity_attention` 选项，`filteredPlaybackEvents()` 中对应分支一并删除（至多筛出 1 条，不构成队列）。
- 时间轴汇总 `#review-timeline-summary` 在待确认为 0 时不再输出该字段，只显示 `N 条 · 已标真 X`；时间轴的橙色 `attention` 标记与图例保留，用于在罕见的停顿点上定位。

# 2026-08-03（第三批）标真手感优化：货框必须人工确认、单人自动选人、Y 乐观跳帧

## 问题

- **算法框被当成人工确认**：`applyAutoConfirmedBoxOnVerify()` 在标真时会把 `ev.box_tokens`（算法检测框）直接写成 `confirmed_box_tokens`。实机上这批检测框误差较大，等于把不可靠的算法结果混进了人工复核数据里，训练时无法区分「人确认过」和「算法猜的」。
- **单人帧仍要点两下**：整段视频大多数帧只有一个人，但侧栏仍要求先点人物卡再点货框，人物卡这一下是纯冗余操作。
- **按 Y 有明显停顿**：`confirmTrueAndNextFrame()` 串行地 `await persistEventReviewToggle()` 再 `await navigatePlaybackFrame(1)`，每帧都要等一次 PATCH 往返才跳帧，连续标注时手感是一顿一顿的。
- **区间标真弹 `window.confirm`**：原生弹窗会抢系统焦点，在全屏专注模式下体验割裂；且纯文本堆叠，明细不好读。
- **侧栏噪音**：模式横幅与模式按钮、标真按钮的信息重复；底部一条快捷键长文与 F1 帮助重复。

## 修改

### 1. 货框必须人工点选才能标真（数据质量）

- `confirmTrueAndNextFrame()` 与 `markActiveEventVerified(true)` 都加同一条前置校验：`getEventConfirmedBoxes(ev)` 与 `getEventEffectiveBindings(ev)` 均为空时拒绝标真，提示「请先在画面上点击货框确认（虚线为算法检测框，仅供参考）」。原先只有 `event_type === "frame"` 才拦，告警 / 碰撞事件会走自动填充。
- **`applyAutoConfirmedBoxOnVerify()` 本身保持不动**：它仍挂在 `setEventVerified()`、`applyEventReviewResponse()` 与 `loadPlaybackEvents()` 上。原因有二 —— 一是历史记录里已落盘的标真帧靠它回填展示，删掉会让旧数据看起来「丢框」；二是「全部标真」批量入口没有逐帧人工点选的机会，删掉会写出空 `confirmed_box_tokens`，反而丢信息。走单帧路径时因为已有人工框，它天然成为空操作。
- **数据格式零变化**：字段名、结构、bindings 语义全部照旧，只是收紧了「什么情况下允许写入」。

### 2. 单人帧自动选中唯一人物（只省点击，不改存盘语义）

- `renderEventReviewPersonUi()` 中新增 `autoSinglePid`：当本帧只有 1 人且尚未手动选人时，人物卡的 radio 直接渲染为选中态。
- 刻意**不写** `pendingPersonIdByKey` 草稿，避免凭空产生「有未保存修改」状态；真正落盘仍由既有的 `applyAutoPersonIdOnVerify()` 在标真时兜底，写出的 `person_id` 与改动前完全一致。
- 单人帧提示文案随货框状态切换：未点框时「已自动选中，点画面货框后按 Y」并标红，点过框后「货框已确认，可按 Y」。

### 3. Y 键乐观跳帧

- `confirmTrueAndNextFrame()` 改为：本地先 `setEventVerified()` + 刷新 UI → 发出 PATCH 但**不等**返回 → 立即 `await navigatePlaybackFrame(1)` → 最后才 `await savePromise`。保存请求本身走既有的 `runSerializedEventReviewSave()` 串行队列，连按 Y 时按顺序排队，不会互相覆盖。
- 失败回滚：PATCH 返回失败时按 `rowKey` 重新定位事件（此时 `playbackEvents` 可能已被整体替换），撤销标真、清 `reviewBackKey`、刷新时间轴，并给出「帧 N 标真未保存已回滚，请用『重试标真保存』」。原有的重试按钮机制不变。
- 新增 `confirmTrueNavigating` 重入锁，防止连按时两次标真落在同一帧上（跳帧完成即释放，不等保存）。

### 4. 页面内二次确认替代 `window.confirm`

- 新增通用弹窗 `#review-confirm-dialog` 与 `openReviewConfirm({ title, lead, rows, notes, confirmText })`，返回 `Promise<boolean>`；无 `showModal` 支持时自动退回 `window.confirm`。
- 区间标真接入该弹窗，**明细一条不减**：帧范围、帧数、配对摘要、每个人物的 raw person_id 逐帧映射各占一行，bindings 写入说明、A/B 跟踪说明、缺人体检测帧数警告作为脚注列表。`R` 键仍是触发入口，保留二次确认的缓冲。
- 确认按钮在 DOM 里排第一（`Enter` 隐式提交落到它上面），视觉顺序由 `flex-direction: row-reverse` 还原为「取消在左、确认在右」；`Esc` 关闭即取消。
- `relocateShortcutsDialog()` 扩展为遍历 `REVIEW_FULLSCREEN_DIALOG_IDS`，让确认弹窗和快捷键帮助一起跟随全屏容器搬家，专注模式下也能正常显示。
- 全局 keydown 增加 `dialog[open]` 判定：模态弹窗打开时页面快捷键让位，避免 `R`、`Y` 穿透到底层。

### 5. 区间落盘成功后自动清空首尾帧

- `applyRangeAnnotVerified()` 的成功分支由 `updateRangeAnnotUi()` 改为 `clearRangeAnnotBounds()`：首帧 / 尾帧标签复位为「—」，首帧模板快照、人工身份锚点一并清空，按钮回到禁用态，提示恢复为「按 A 设首帧、D 设尾帧」。连续标注下一段时直接按 A 即可，不必先按 Shift+R。
- 清空放在 `persistEventReviewRange()` 之后执行，`clearRangeAnnotBounds()` 只写 `#event-range-*` 相关元素、不碰 `#event-save-status`，所以「区间标真完成 · 帧 a–b · 共 N 帧」这条结果提示会保留在原位。
- 失败分支不清空，区间保持原样，配合既有的「重试区间保存」按钮可直接重试。

### 6. 侧栏降噪

- 删除 `#event-review-mode-banner`：单帧模式下的「当前操作只影响帧 N」与标真按钮上的帧号重复，区间模式下的帧范围与区间面板的首帧 / 尾帧标签重复。
- 删除底部 `.event-review-kbd-hint` 长条，快捷键统一由 F1 帮助承载。
- 相应清理 `updateEventReviewModeUi()` 中的横幅分支与两块 CSS（含 1100px 断点下的横幅规则）。

# 2026-08-03（第四批）记录列表触底自动加载

## 背景

- 本批基于师姐 `f3b640b feat(playback): integrate camera list into review branch`，该提交把回放记录列表从「单层扁平分页 + 客户端分组」改成「一级机位摘要（`/api/record-cameras` 全量返回）+ 二级机位内记录分页」，机位层面已经不需要反复加载。
- 但二级仍是 `RECORD_LIST_PAGE_SIZE = 200` 的手动分页：`renderRecordsLoadMoreFooter()` 只在 `state.hasMore` 时渲染一个「加载更多记录…」按钮，`loadMoreRecords()` 也只由该按钮的 click 绑定触发，全文件没有 scroll / IntersectionObserver。机位下记录超过 200 条时，仍要一直点按钮才能看到全部。

## 修改

- `renderRecordsLoadMoreFooter()` 在还有下一页时，于页脚插入零高度哨兵 `<span class="playback-records-sentinel">`；「加载更多记录…」按钮保留，作为不支持 `IntersectionObserver` 与键盘操作的降级入口。
- 新增 `observeRecordsAutoLoad(list)`：以 `#session-list`（即滚动容器 `.playback-records-list`）为 `root`、`rootMargin: "240px 0px"` 观察哨兵，进入视野即调用 `loadMoreRecords()`。提前 240px 触发，滚到底时下一页通常已经在路上。
- 观察器存在模块级变量 `recordsAutoLoadObserver`，`bindRecordListEvents()` 每次重渲染都先 `disconnect()` 再重挂 —— 列表用 `innerHTML` 整体替换，旧哨兵节点会被丢弃，不断开会残留观察器。
- 去重依赖既有逻辑：`loadMoreRecords()` 开头已有 `if (!state.hasMore || state.loadingMore) return;`，加载中页脚渲染的是「加载更多…」文本而非哨兵，所以不会连环触发；一页 200 条足以把哨兵顶出视野，`hasMore` 为 false 时页脚只剩进度文本，自动加载自然停止。
- 机位层（未选中机位）`renderRecordsLoadMoreFooter()` 直接返回空串，没有哨兵，观察器会被断开，不影响一级列表。
- 后端与 API 未改动，`RECORD_LIST_PAGE_SIZE` 维持 200。

| 文件 | 改动 |
|------|------|
| `web/app/06-records.js` | 页脚哨兵、`observeRecordsAutoLoad()`、`bindRecordListEvents()` 挂载观察器 |
| `web/style.css` | `.playback-records-sentinel` 零高度块级元素 |
| `web/index.html` | `06-records.js` 与 `style.css` 版本号 |
| `tests/test_event_review_workspace.js` | 断言哨兵、`IntersectionObserver`、观察器挂载 |

# 2026-08-03（补丁）补齐 workspace 键盘监听的模态弹窗让位

## 问题

- 第三批给 `11-playback-controls.js` 的 `keydown` 加了 `dialog[open]` 判定，但漏了 `12-event-review-workspace.js` 里的那一个。
- 后果：快捷键帮助（F1）或区间二次确认弹窗打开时，`F` 仍会切换专注模式全屏、`Tab` 仍会切换单帧/区间模式、`Ctrl+Z` 仍会撤销，按键穿透到底层页面。在确认弹窗上尤其危险 —— 用户以为在跟弹窗交互，实际改了底层状态。

## 修改

- `12-event-review-workspace.js` 的 `keydown` 监听在 `isReviewTypingTarget()` 判定之后补 `if (document.querySelector("dialog[open]")) return;`，与 `11-playback-controls.js` 保持一致。

## 说明：专注模式快捷键

- 专注模式的快捷键在第二批就已绑定为 `F`，F1 帮助表中有对应条目，本次无需新增。
- 选 `F` 的理由：与主流播放器（YouTube / B 站 / VLC）的全屏键一致；且不与复核现有按键冲突（`Y`/`U` 标真、`A`/`D`/`R` 区间、`Tab` 模式、`Alt` 换人、`G` 跳帧、`N` 下一条、`1`/`2` 选人、`Space` 播放、`Ctrl+Z` 撤销、`F1` 帮助）。
- 退出除再按 `F` 外，浏览器原生 `Esc` / `F11` 也可退出，`fullscreenchange` 会把状态回写到按钮与 `body` class。

| 文件 | 改动 |

| `web/app/12-event-review-workspace.js` | keydown 增加 `dialog[open]` 让位判定 |
| `web/index.html` | `12-event-review-workspace.js` 版本号 |

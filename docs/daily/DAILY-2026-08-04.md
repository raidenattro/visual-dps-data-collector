## 问题一：`跳转到具体帧` 文字显示在界面上

`<span class="sr-only">跳转到具体帧</span>`，但 `.sr-only` 全项目只用了这一处、
**CSS 里从来没有定义过**，所以这个本该只给读屏软件的文字直接渲染成了可见蓝字。
输入框自己已有 `aria-label="跳转到具体帧"`，这个 span 对读屏也是重复的，直接删掉。

## 问题二：播放时货框紫色与人物配对色完全不出现

昨天修好了播放时的人形框与碰撞红黄色，但**人工确认色仍只在暂停时显示**，
即昨天日志里「仍未覆盖」的那条。根因是按帧取事件是全表扫描：

- `getEventsOnFrame()` 是 `playbackEvents.filter(...)`，
- `getReviewBoxHighlightContext()` 里也 `for (const ev of playbackEvents)` 扫一遍。

一条记录上万条事件，放进每帧热路径不可接受，所以复核高亮长期被排除在播放之外。

人物标签还有第二个原因：配对色只在 `getPinnedPlaybackEvent()` **恰好落在当前帧**时才取，
而播放时钉住的事件几乎永远不是当前帧，于是标签一路是灰的。

## 修改

- 新增帧 → 事件索引（`08-event-review.js`）。`playbackEvents` 只会整体替换、
  从不原地增删，所以用数组身份判断失效就够。索引只存**事件引用**，标真/配对状态仍每次
  实时读，所以标注完立刻生效、不会看到旧高亮。`eventMatchesPlaybackFrame` 认
  `frame_idx` 与 `source_frame_idx` 两者之一，索引两边都挂。
  `getEventsOnFrame()` 返回副本，避免调用方增删污染索引内部。
- `getReviewBoxHighlightContext()` 改走索引，于是可以进播放热路径。
- 把单个货框的上色决定提成 lite/full 共用的 `resolveAnnotationBoxState()` +
  `paintAnnotationBox()`。**两条路径各留一份颜色决定，正是这类 bug 反复发生的根源**，
  所以是合并而不是往 lite 里再抄一份。`drawAnnotationBoxesCollisionOnly` 改名为
  `drawAnnotationBoxesAccentOnly`：淡绿底色已在烘焙静态层里，播放时只补需要上色的框
  （人工确认 / 漏报误报 / 碰撞告警），跳过 plain 的那些。
- 人物标签：钉住事件不在当前帧时，回退到**本帧自己的标真事件**取配对色。
  同时放宽 lite 的单人帧跳过条件——已配对的单人帧也要出颜色。

## 未改动

（`updateReviewConflictBar`），放进播放路径会变成每帧写 DOM。

# 2026-08-04 冲突描边拆出侧栏更新，播放时也画

## 问题

`drawReviewConflictOutlines()` 把两件事捆在一起：算冲突 + 画描边（画布），以及
`updateReviewConflictBar()`（写侧栏 DOM）。捆在一起就只能挂在暂停/seek 的 full 路径上
—— 放进播放路径等于每帧写一遍 DOM。于是漏标/标错嫌疑的虚线播放时看不到，
而漏标恰恰要靠完整看过去才能发现。

## 修改

- `drawReviewConflictOutlines()` 只算与画，不碰 DOM，lite/full 两条路径都调用。
- 侧栏拆成两层：
  - `updateReviewConflictBar()`：无条件写 DOM，留给模式切换等场景。
  - `syncReviewConflictUiForFrame(frameIdx)`：绘制路径每帧调，只做两件便宜的事——
    翻帧收回编辑态（纯状态判断），以及**内容签名变了才写 DOM**。
- 签名 `reviewConflictBarSignature()` 只含三类冲突的数量与悬空 id，**不含帧号**：
  帧号不显示在条上，含进去会每帧都判为脏，等于没做节流。
- 侧栏同步放在 `drawSkeletonFrame` 里统一调一次，不在两条绘制分支里各调一遍。

计算成本本身已经不是问题：`getVerifiedEventsOnFrame` 走上一节的帧索引，
`getFramePersonIds` 是一次 `frameCache.get`，其余是几十个货框的集合判断。

## 验证

`test_event_review_workspace.js` 补断言：描边函数内不许出现
`updateReviewConflictBar|classList|textContent`（否则又会退回不能进播放路径的状态）、
lite 与 full 都调描边、签名不含帧号、绘制路径只调节流版。JS 测试 12 个文件全过。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `web/app/14-event-review-recheck.js` | 描边与侧栏拆开，侧栏加内容签名节流 |

# 2026-08-04 货框与人员高亮：干掉热路径上的三处重复计算

## 问题

上面几节把人工确认色、配对色、冲突描边都补进了播放路径，功能对了，但这些计算原本只在
暂停时跑一次，现在每帧都要跑。逐个看下来，热路径上有三处**每帧重算却结果不变**的地方：

1. **`boxTokenLookupKeys()` 每次调用都遍历全部货框比字符串。** 它负责把
   `Box_2011` 与 `A1:2011` 这类不同写法归一。而 `resolveAnnotationBoxState()` 每个货框
   要调五次（告警 / 碰撞 / 人工确认 / 漏报 / 误报），冲突判定再三次。
   30 个货框就是每帧约 240 次查找 × 30 次遍历 ≈ **7200 次 `String().trim()`**，
   外加 240 个临时 `Set` + 数组。这是这次最大的一块。
2. **`getReviewPersonAccentStyle()` 每次调用都重建整个调色板**——4 个对象字面量加一个
   数组，只为按下标取一个。它每人每帧、每个配对每帧各调一次。
3. **人物标签宽度每人每帧量一次 `measureText()`**，而文本只有「人物1」「P0」这几种。

## 修改

- `boxTokenLookupKeys()` 加按 token 的缓存，原逻辑挪进 `computeBoxTokenLookupKeys()`。
  失效判断用 `annotationBoxes` 的**数组身份 + 长度**，不依赖各处赋值点记得手动清缓存：
  货框只会整体替换，唯一的原地 `push` 是 shelves 分支先赋空数组再填，长度会变，能被抓到。
  全项目没有任何地方原地改 `box_id`，所以这个判断是充分的。
  返回值改成**共享冻结数组**——七个调用点全都只是 `for...of` 遍历，冻结后真有人去 `push`
  会立刻抛错，而不是静默把缓存改坏。
- 调色板提成模块级 `REVIEW_PERSON_ACCENT_PALETTE`，逐项冻结。
- 新增 `measureLabelWidth(text, font)`，按「字体 + 文本」缓存宽度
  （`measureText` 不受 ctx 变换影响，只取决于这两者）。
  只在**未命中时**才碰 `ctx.font` 并原样还原——否则就会给调用方留下时有时无的字体状态，
  比一直不还原更难查。命中测试 `hitTestPersonDetailAtClient()` 改用同一个函数，
  命中框与画出来的标签从此不可能量出两个宽度。

## 验证

新增 `tests/test_render_hotpath_caches.js`，三处缓存都**用计数证明**而不是只看代码长相：

- token 缓存：先验等价性（`Box_` / `shelf:id` / 空值 / 首尾空格），再模拟 30 帧绘制
  （3 货框 × 8 次查找 = 720 次调用），断言全表扫描恰好只发生 **3** 次；
  换数组、以及**同长度换数组**（换记录后货框数恰好相同）都必须重算；共享数组必须冻结。
- 配对色：同一稳定身份两次调用必须返回**同一个对象**，四色循环，对象已冻结。
- 标签宽度：2 人 × 30 帧断言只量 **2** 次；换字体要重量；量完 `ctx.font` 必须还原。

`test_person_canvas_hit.js` 原来把命中函数单独切进 VM，现在要把 `measureLabelWidth`
真实实现一起切进去（而不是给个替身），才守得住「两处宽度同源」这条。
JS 测试 13 个文件全过。

|------|------|
| `web/app/10-render-collision.js` | token 查找加缓存；新增标签宽度缓存并给命中测试复用 |
| `web/app/08-event-review.js` | 配对色调色板提到模块级 |

# 2026-08-04（性能）长视频回放：派生预览、Arrow 缓存、按需骨骼与有界 DOM

## 问题

- 28,096 帧记录首次打开时，前端曾连续请求整条记录的骨骼分块；事件、复核列表与时间轴也会
  同时建立大量 DOM，导致首开、拖动和播放相互争抢主线程。
- schema v2 的 `timeline.parquet` / `skeleton.parquet` 是单 Row Group。原实现每个 200 帧
  `/frames` 请求都重新读取 Parquet，拖到长视频中后段仍要重复做整表 IO。
- 原视频分辨率较高、关键帧间隔不受控时，浏览器首次加载和远距离 seek 较慢。早期预览方案若
  改变帧率、补帧或帧数，则会让视频画面与骨骼、碰撞事件发生错帧。
- 播放热路径同时刷新骨骼、整条事件时间轴和复核面板，视频解码稍有积压时会放大成明显掉帧。

## 修改

### 1. 只给真正的长视频生成独立 480p 预览

- 预览资格只看帧数：源视频 **帧数不少于 10,000** 即生成预览，不再以源视频高度作为
  前置条件；短视频直接使用原片。源高度已经等于或低于 480 时仍会重新编码，以获得
  fast-start 和约 1 秒 GOP 的 seek 性能。
- 预览为 H.264、无音频、`+faststart`、零起始 PTS，GOP 按源帧率换算为约 1 秒。
- 保持源帧率和帧数，不抽帧、不补帧。转码完成后再次探测，预览帧数与源视频不相等即删除
  并回退原片。
- 缓存键包含源路径、大小、修改时间和目标高度，写到独立
  `localdata/playback-cache/video`，不覆盖原视频，也不在共享数据目录旁生成文件。
- 首次缓存未命中时页面立即播放原片，后台只启一个转码任务；下次打开自动使用预览。
- Windows GPU 依赖增加 `imageio-ffmpeg`，系统 ffmpeg 不可用时使用其内置可执行文件。
- 新增 `scripts/dev/prewarm_playback_previews.py`，可在服务启动前批量预热本地记录。

### 2. 视频、时间轴、骨骼和碰撞统一帧域

- 回放前校验 `video == manifest == timeline` 的总帧数，timeline 帧号域必须为 `1..N`。
- `skeleton.parquet` 允许没有检测到人的稀疏帧，但最小/最大帧号不得越出 `1..N`；碰撞事件
  继续使用 timeline 的有效帧号。
- 任一关键帧数不一致时 `/video` 拒绝使用错误预览，预览状态接口返回明确诊断；不会用临近帧
  骨骼掩盖错位。
- 采集存档始终原样复制源视频，回放配置中的 `transcode_height` 不再影响采集视频保存。

### 3. 后端只读 Arrow LRU 与 HTTP 诊断

- 新增线程安全的记录级 Arrow LRU：最多 8 条记录、总内存 256 MB。
- 缓存键包含 timeline / skeleton 文件大小和纳秒修改时间，文件变化后自动失效；超限按 LRU
  淘汰，服务重启后自然清空。
- `/frames` 通过有序帧号二分定位并对 Arrow Table `slice`，不再每次扫描 Parquet。
- `/timeline?light=1` 和事件定义复用缓存；`event_review.json` 仍在每次事件响应时重新读取并
  叠加，避免返回过期标真状态。
- FastAPI 启用 1 KB 阈值 GZip；timeline、events、frames 增加 `Server-Timing` 与
  `X-Playback-Cache: hit|miss`，JSON 字段和现有 URL 均不变。

### 4. 骨骼按需加载与请求隔离

- 骨骼按 200 帧分块。打开记录只并行加载当前附近 2 块，播放时向前预取最多 3 块，移除
  全记录后台预取。
- 前端最多保留 16 个分块，按 LRU 淘汰；已淘汰分块允许再次请求。
- 每条记录使用独立 `AbortController` 与 generation。切换记录会取消旧 timeline、events、
  frames 和预览状态请求，旧响应不得写入新记录缓存。
- 目标帧骨骼尚未到达时清空覆盖层并显示轻提示，不显示上一帧、临近帧或上一条记录的骨骼。

### 5. 首开与播放热路径解耦

- manifest、视频状态、timeline、标注和首批骨骼并行加载；视频、timeline 和首块骨骼就绪
  即可操作。events 在后台加载，只暂时禁用复核操作，不阻塞播放和拖动。
- 播放覆盖层最多绘制 15 FPS，只处理最新一帧、不补历史绘制；暂停、逐帧和事件跳转仍精确
  绘制目标帧全部内容。
- 复核面板播放时最多 250 ms 更新一次，不自动滚动列表、不重建人员选项；浏览器解码掉帧
  时优先跳过覆盖层，不修改视频时间轴。
- 保留最新版的帧事件索引、人工确认色、人员配对色、collision tracker、冲突描边、
  `person_track_id` 回填与同帧去重逻辑。

### 6. 不使用 Canvas 替换事件时间轴

- 事件轨与人工复核轨继续使用按容器宽度生成的 DOM 像素桶，每 4 px 一个桶；两轨共享桶
  模型，节点数与容器宽度有关，不随 28,096 条事件线性增长。
- 播放只移动单个 DOM 游标并更新相邻 active 桶；标真/绑定变化只更新受影响桶，筛选、事件
  集合或桶数量变化时才使用 `DocumentFragment` 整体重建。
- 尺寸变化由 `ResizeObserver` 合并处理。
- 复核列表采用固定行高虚拟滚动，完整事件数组仍保留，页面实际最多渲染 80 个事件行和上下
  两个占位行；点击、勾选、筛选、键盘导航、标真与保存 schema 不变。

## 日志与诊断

- 后端 INFO 日志记录预览选择、转码排队/开始/完成、Arrow 冷加载、骨骼延迟加载、缓存失效、

```js

location.reload();
```

  此时会输出分块加载/淘汰、generation 重置、`Server-Timing`、缓存命中头和虚拟列表窗口。
  完成排障后执行 `localStorage.removeItem("visual-dps-playback-debug")`。
- Windows 后台启动日志固定使用 UTF-8；PowerShell 查看时应使用
  `Get-Content -Encoding utf8`，避免把控制台 GBK 解码造成的显示乱码误认为文件损坏。

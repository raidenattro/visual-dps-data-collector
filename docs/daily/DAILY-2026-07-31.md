# 2026-07-31 区间标真修复记录

## 问题

1. 首帧已经点选货框，切到尾帧操作后首帧模板被刷新为空，区间提交时再次要求标首帧货框。
2. 同一物理人员跨帧可能从 P0 变为 P1，区间保存不能把首帧 person_id 复制到全部帧。

## 修改

- 首帧模板在离开首帧后冻结：
  - 自动刷新不再覆盖已有快照；
  - 尾帧或中间帧的货框/person 操作不能修改首帧模板；
  - 只有首帧上的显式货框或人员操作能分别更新对应字段；
  - 返回首帧时，旧事件的 pending 状态为空也不会清除已缓存货框。
- 区间人员身份按帧保存：
  - 单候选帧即使 raw person_id 从 P0 变成 P1，也按本帧写入 P1；
  - 多人同时出现但目标人体框轨迹稳定时，按相邻帧空间连续性自动跟踪，不再逐帧打断；
  - raw person_id 的 P0/P1 重排会自动映射，不再被当成人物变化；
  - 仅在遮挡后重现或空间连续性置信度不足时暂停人工确认；
  - 人工确认后自动继续定位下一处变化点，可按 `1` 快选 P0、按 `2` 快选 P1；
  - track 只保留为弱参考，不能覆盖人体框空间连续性的判断；
  - 最终确认框显示人员分段摘要，例如 `100:P0，101–105:P1`；
  - 后端回归验证 schema v2 文件中每帧保留各自 person_id 与 track。
- 设置尾帧后明确提示首帧货框已冻结，尾帧无需重复选择货框。

## 验证

- JavaScript 区间身份与首帧快照回归通过。
- Python 事件复核、schema v2 和下游回归共 25 项通过。
- 本轮修改仅在本地工作区，尚未提交或同步服务器。

## 同帧 P0/P1 往返稳定性

- 定位到逐帧跳转时存在两层问题：
  - 精确 `frame_idx` 被换算为视频时间后再次映射，容器 PTS 偏移可能把 157 帧骨架映射到邻近帧；
  - 连续点击上一帧/下一帧时，较早的异步 seek 可能晚完成并覆盖最新画布。
- 修复后：
  - 精确逐帧和事件跳转直接按 `frame_idx` 获取骨架；
  - seek 使用递增序号丢弃过期异步结果；
  - 对本地 `00000000907002300_seg10_26-05_to_26-42` 实测 157→156→157，最终画布、侧栏与权威帧均为 157；
  - 157 帧始终读取左侧 raw P1/track 2、右侧 raw P0/track 1。

## 全视频稳定人物身份与首次加载优化

- 新增与 raw `person_id` 分离的稳定人物层：
  - 画面和复核选项使用“人物 A / 人物 B”作为跨帧主身份；
  - 相邻帧人体框空间连续性与运动方向预测优先，解决两个人交叉时仅凭 IoU 容易交换 A/B 的问题；
  - track 仅用于断帧后的弱提示，不能覆盖运动轨迹；
  - 稳定身份编号不循环复用，离场人员不会因为左右空位变化直接与新人员交换 A/B；
  - 每一帧保存时仍写入该帧真实 raw P0/P1，保持原数据格式和下游兼容；
  - 原始 P0/P1 仅显示在右侧详情中，画面主标签不会再随检测顺序左右交换；
  - 后台加载后续骨架分块时不再无条件清空当前稳定身份，避免画面回跳后编号突然变化。
- 画面点选人员：
  - 可直接点击完整“人物 A/B”标签；
  - 也可点击人体检测框内部或骨架关键点附近；
  - 命中后仍转换为该帧真实 raw person_id 保存，不改变数据格式。
- 左侧记录加载流程优化：
  - 单击记录即自动加载，不再要求“先选中、再点加载”或双击；
  - 同一时间只允许一个加载请求，避免连续点击产生并发加载和状态覆盖；
  - 首次只等待首个骨架分块，视频与标注就绪后其余分块在后台预取。
- 验证：
  - JavaScript 稳定身份（含双人交叉）、画面点人、区间身份和精确逐帧测试通过；
  - Python 事件复核、schema v2 和下游回归共 25 项通过；
  - 本地双人测试视频 868 帧中，raw P0/P1 共发生 76 次重排，稳定人物身份发生 0 次交换（track 2 始终为人物 A，track 1 始终为人物 B）；
  - 本地 `8767` 页面实际加载新脚本后，执行 `157 → 156 → 157`，权威帧、已渲染帧均稳定回到 157；
  - 关键帧实测：156/157 帧左侧为人物 A（raw P1）、右侧为人物 B（raw P0）；160 帧 raw P0/P1 对调后，左侧仍为人物 A、右侧仍为人物 B，页面无脚本错误。

## 手部与货框重叠时无法点选

- 原因：画布旧逻辑先判断人物，人体检测框覆盖整个身体和手部；货框与人体框重叠时，点击会被提前识别为“选择人物”；
- 修复点击优先级：
  - 明确点击“人物 A/B”文字标签时选择人物；
  - 点击货框多边形时优先选择货框，即使同时落在人体框或骨架关键点范围内；
  - 没有点中货框时，骨架关键点和人体框仍可用于选择人物；
- 本地第 116 帧实测：Box_2016 中心点同时命中人物 A 的人体框，真实鼠标点击后暂选结果正确变为 `Box_2016`；
- 人物画布命中、稳定人物、精确逐帧及 Python 后端回归均通过。

## 所有视频回放进度条对齐

- 原因：旧进度条使用 `timeline 时间 / video.duration`，当视频容器时长、PTS 与骨架 timeline 长度不一致时，最后一帧只能走到进度条中间或约 80%；
- 进度条改为优先使用当前权威帧在实际 `frameByTime` 索引中的位置：
  - 首帧固定为 0%；
  - 中间帧约为 50%；
  - 最后一帧固定为 100%；
- 拖动进度条时也反向映射到真实帧索引，不再按视频 duration 猜测帧号；
- HTML5 视频触发 `ended` 后主动渲染最后一帧、更新复核帧号并把进度补到 100%；
- 本地 6 条不同长度记录（629、1653、2084、1207、2831、868 帧）逐条验证首/中/末位置及拖到最右结果，全部正确，页面无脚本错误。

## 播放控制与事件导航解耦

- “播放”“暂停”合并为一个按钮：播放时显示“暂停”，暂停时显示“播放”，空格键行为一致；
- 明确事件与视频的单向绑定关系：
  - 视频播放是时间轴主控；
  - 播放过程中，右侧当前事件、事件序号和列表高亮只跟随视频帧更新；
  - 事件自动切换不得暂停视频、修改 `currentTime` 或把画面拉回事件帧；
- 移除以下隐式事件跳转：
  - 记录/标注加载完成后自动跳第一条事件；
  - 切换事件筛选后自动跳第一条事件；
  - 点击事件表格行或进度条事件标记后直接 seek；
- 上述操作现在只更新右侧选中事件；只有用户触发“上一条/下一条事件”导航时才调用 `seekToEvent`，暂停并跳到目标事件帧；
- 播放中即使残留旧的事件钉住状态，也会强制进入单向跟随模式，不再执行自动回拉；
- 本地真实页面验证：播放期间事件从第 17 帧跟随至第 29 帧，视频持续播放且时间连续；点击“下一条”后才暂停并锁定目标事件帧，页面无脚本错误。

## 统一逐帧导航控件与快捷键

- 在视频下方新增统一帧导航条：首帧、后退 10 帧、后退 1 帧、播放/暂停、前进 1 帧、前进 10 帧、尾帧和指定帧输入。
- 移除事件复核卡片内重复的“上一帧 / 下一帧 / 当前帧 / 总帧数”控件，逐帧操作统一由视频导航条负责。
- 快捷键：
  - `Space`：播放/暂停；
  - `←` / `→` 短按：后退/前进 1 帧；
  - `←` / `→` 长按：按视频帧率 3 倍速连续后退/前进；
  - `Ctrl+←` / `Ctrl+→`：后退/前进 10 帧；
  - `Home` / `End`：跳到首帧/尾帧；
  - `G`：聚焦指定帧输入框，输入后按 `Enter` 跳转。
- 所有帧按钮、输入框和快捷键复用同一套精确逐帧跳转逻辑；只有显式使用上一条/下一条事件时才触发事件导航。
- 修复首尾帧快速切换时指定帧输入框可能残留旧帧号的问题，显式跳帧完成后强制按权威目标帧同步输入框。
- 连续快速操作采用“最后一次导航生效”的序号保护，较早且较慢完成的 seek 不再反向覆盖最新帧、复核卡片或输入框。

## 二、已修复问题（`fix/video-playback-bug`）

### 2.1 刷新 event_total 时标注被覆盖（commit `9835262`）

| 项 | 内容 |
|----|------|
| 现象 | 后台刷新 `event_total` 与用户保存标真并发写 `event_review.json`，后写覆盖先写，已保存标注丢失 |
| 根因 | 写入无锁；非原子写 JSON |
| 修复 | `Lock` → 可重入 `RLock`；新增 `_write_json_atomic()` 临时文件 + 原子替换；`save_event_review` / `cache_event_review_total` 等统一加锁 |
| 涉及 | `pose_store.py`、`tests/test_event_review_concurrency.py` |

### 2.2 同帧多货框标真返回后丢失或错显

| 项 | 内容 |
|----|------|
| 现象 | 如第 1272 帧同时有 `Box_2014`、`Box_2015`，标真 `Box_2015` 后切帧再回来，可能未标真或显示成 `Box_2014` |
| 根因 | 旧逻辑同帧按货框拆多条；点击货框会切换当前事件；加载时「事件类型 + 帧号 + 货框」匹配易错配 |
| 修复 | 同帧聚合为一条帧级记录；点击货框只更新确认货框不切换事件；标真/取消按帧写入并清理同帧旧重复条目 |
| 涉及 | `pose_store.py`、`api/routes/http.py`、`web/app/08-event-review.js`、`web/app/10-render-collision.js` |

### 2.3 「标为真 · 下一条」画面不前进

| 项 | 内容 |
|----|------|
| 现象 | 点绿色按钮后列表序号变，视频仍停同一帧（「下一条」可能是同帧另一货框事件） |
| 修复 | 按钮改为 **「标为真 · 下一帧」**；保存成功后 `navigatePlaybackFrame(1)`；快捷键 `Y` 同步 |
| 涉及 | `web/app/08-event-review.js`、`web/app/11-playback-controls.js`、`web/index.html` |

### 2.4 「取消标真 · 下一条」误按整个事件取消

| 项 | 内容 |
|----|------|
| 现象 | 一次取消作用于整个碰撞事件段，不符合逐帧判断需求 |
| 修复 | 按钮改为 **「取消标真 · 下一帧」**；`drop_review_frame(frame_idx)` 只清当前帧；快捷键 `U` 同步 |
| 涉及 | `api/routes/http.py`、`web/app/08-event-review.js` |

### 2.5 复核队列改为逐帧模式

| 项 | 内容 |
|----|------|
| 原行为 | 队列只含告警/碰撞事件；同帧多货框多条记录 |
| 新行为 | 每视频帧一条记录；无检测事件用 `event_type: "frame"`；同帧告警/碰撞/货框合并展示 |
| 约束 | 普通帧须先点选画面货框再标真，防止空标真 |
| 涉及 | `pose_store.load_events()`、`web/app/08-event-review.js`、`web/style.css` |

### 2.6 普通帧取消标真报 `event 字段无效`

| 项 | 内容 |
|----|------|
| 现象 | 普通帧已标真 `Box_2012 / P0`，点取消后报红错，货框变横杠 |
| 根因 | 前端乐观更新先清空货框/人员；普通帧无检测框时后端校验失败；失败回滚不完整 |
| 修复 | 取消前保存 `previousPayload`；后端允许合法普通帧号取消；失败时恢复标真状态、货框、`person_id` |
| 涉及 | `api/routes/http.py`、`web/app/08-event-review.js`（`unmarkTrueAndNextFrame`） |

### 2.7 无碰撞刷新保留旧标真

## 三、Legacy 数据遗留问题（重要，合并前需知情）

旧版 `verified_true` 为「**同帧、按货框一条**」格式。`seg07` 等生产数据量大，且含同帧重复/错配条目（799 条 → 786 帧）。以下问题在 **legacy 数据加载与迁移** 时仍有风险。

### 3.1 【高】加载聚合：无 confirmed 时误用 box_tokens（`pose_store.py:1177-1179`）

**代码逻辑：**

```python
for cand in legacy_items:
    cand_confirmed = extract_confirmed_box_tokens(cand)
    confirmed.extend(cand_confirmed or list(cand.get("box_tokens") or []))
```

**问题：** 某条 legacy 无 `confirmed_box_tokens` 时，把 **模型检测框 `box_tokens`** 当作 **已确认货框** 合并。

**示例（第 1272 帧）：**

| legacy 条目 | box_tokens | confirmed_box_tokens |
|-------------|------------|----------------------|
| A | `["Box_2014"]` | （无） |
| B | `["Box_2015"]` | `["Box_2015"]` |

**加载结果：** 页面显示已确认 `Box_2014` + `Box_2015`，用户实际只标了 `Box_2015`。

**影响范围：**

| 场景 | 后果 |
|------|------|
| 只打开视频浏览 | 货框/Person 展示错误；**JSON 尚未被改写** |
| 导出 Excel | 误合并货框写入导出文件 |
| 误导后续操作 | 用户以为两个都对，或触发 3.2 迁移写坏 |

### 3.2 【中高】重新标真/迁移：只取首条 legacy + 回退全量检测框（`api/routes/http.py:1261-1270`）

**代码逻辑：** 用户再次标真（legacy → 新帧级格式）时，若请求无 `confirmed_box_tokens`：

1. 只从 **第一条** legacy 取 confirmed
2. 仍无 → 用该帧 **全部** `norm["box_tokens"]`

**问题：** 与 3.1 串联时，一次「重新标真」或误触迁移会把 **错误货框永久写入** 新格式，并删除同帧全部 legacy 条目，**难以从文件恢复**。

**示例：** legacy 顺序 `[A, B]`，A 无 confirmed → 写入 `["Box_2014", "Box_2015"]`，覆盖用户真实选择 `Box_2015`。

**与 3.1 关系：**

```
旧 event_review.json → [3.1 加载错显] → 用户再次标真 → [3.2 写入错数据] → legacy 被覆盖
```

### 3.3 【中】「全部标真」跳过普通帧（`pose_store.py:724-738`）

| 项 | 内容 |
|----|------|
| 现象 | 逐帧模式下「全部标真」前端乐观勾选全部帧，服务端 `events_to_verified_entries` 跳过无 `box_tokens` 的 `frame` 类型 |
| 后果 | 刷新后大量普通帧仍为未标真，与「已全部标真 · 共 N 条」提示不符 |
| 影响 | 若业务不要求普通帧批量标真，风险较低；若需要全帧标真完成态，需单独修复 |

### 3.4 【中】列表勾选取消缺少完整回滚（`web/app/08-event-review.js:1636-1642`）

| 项 | 内容 |
|----|------|
| 现象 | 右侧列表取消标真未像 `unmarkTrueAndNextFrame` 那样保存 `previousPayload` |
| 后果 | 普通帧取消请求失败时，货框/`person_id` 不会恢复（主按钮路径已修，此处遗漏） |
| 影响 | 与 2.6 同类 bug 的次要入口 |

## 四、建议修复方向（Legacy，待实施）

| 问题 | 建议 |
|------|------|
| 3.1 加载聚合 | 仅合并 `confirmed_box_tokens`；无 confirmed 的 legacy 条目不回退 `box_tokens` |
| 3.2 迁移写入 | 合并 **所有** legacy 的 confirmed 并集；禁止无 confirmed 时默认全量 `box_tokens` |
| 3.3 全部标真 | 明确产品语义：是否包含普通帧；若包含则要求 confirmed 或跳过并提示 |
| 3.4 列表取消 | 与 `unmarkTrueAndNextFrame` 对齐：取消前快照 + 失败完整回滚 |

**建议补测：** 同帧多条 legacy、仅一条带 `confirmed_box_tokens` 的加载与 toggle 迁移用例。

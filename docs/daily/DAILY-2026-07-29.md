## 三、Legacy 数据遗留问题（重要，合并前需知情）

旧版 `verified_true` 为「**同帧、按货框一条**」格式。`seg07` 等生产数据量大，且含同帧重复/错配条目（799 条 → 786 帧）。**§3.1/3.2 的运行时读路径与 toggle 全量 fallback 已通过 v2 只读 + v2 写入缓解**；存量 legacy 须先跑迁移脚本，否则页面不展示历史标真。

### 3.1 【已缓解】加载聚合误用 box_tokens

| 项 | 内容 |
|----|------|
| 原问题 | legacy 读时聚合，无 `confirmed` 的条目误用 `box_tokens` 合并展示 |
| 现状 | `load_event_review` / `enrich` 只读 v2；legacy 文件返回空标真（须先迁移） |
| 残余 | 未迁移文件打开时看不到历史标真；导出/评估等旁路若读 raw legacy 仍可能误用 |

### 3.2 【已缓解】重新标真回退全量检测框

| 项 | 内容 |
|----|------|
| 原问题 | toggle 无 `confirmed` 时写入全量 `norm["box_tokens"]` |
| 现状 | 已删除 fallback；无确认货框返回 400；落盘经 v2 `bindings` |
| 残余 | 迁移前 legacy 磁盘文件仍须 `--write` 一次性转换 |

### 3.3 【中】「全部标真」跳过普通帧（`pose_store.py:724-738`）

| 项 | 内容 |
|----|------|
| 现象 | 逐帧模式下「全部标真」前端乐观勾选全部帧，服务端 `events_to_verified_entries` 跳过无 `box_tokens` 的 `frame` 类型 |
| 后果 | 刷新后大量普通帧仍为未标真，与「已全部标真 · 共 N 条」提示不符 |
| 影响 | 若业务不要求普通帧批量标真，风险较低；若需要全帧标真完成态，需单独修复 |

### 3.4 【中】列表勾选取消缺少完整回滚（`web/app/08-event-review.js:1636-1642`）

| 项 | 内容 |
|----|------|
| 现象 | 右侧列表取消标真未像 `unmarkTrueAndNextFrame` 那样保存 `previousPayload` |
| 后果 | 普通帧取消请求失败时，货框/`person_id` 不会恢复（主按钮路径已修，此处遗漏） |
| 影响 | 与 2.6 同类 bug 的次要入口 |

## 八、迁移工作注意事项

本节汇总 **legacy → schema v2** 离线迁移的操作要点、兼容范围与风险，供执行 `--write` 前对照。详细规则见 `docs/migrate-event-review-frame-v2.md`。

### 8.1 前置条件（必做）

| 顺序 | 项 | 说明 |
|------|-----|------|
| 1 | 代码版本 | 须含 **v2 读**（`f0da6d8`）+ **v2 写**（`fcbe44b`）；仅迁移不升级代码，页面仍可能读不到或再次写坏 |
| 2 | 停写窗口 | 迁移期间避免多人同时标真同一机位；脚本会整文件替换 `event_review.json` |
| 3 | 备份 | `--write` 自动在同目录生成 `.bak.{timestamp}`；大批量前建议额外复制 `localdata/review/` |
| 4 | 预览 | **必须先** `--dry-run`，核对 `would_migrate` / `cleared_frames` / `warnings` |

### 8.2 可迁移的 legacy 格式

以下均为 **schema 1**、`verified_true[]` 扁平行，**`fix/video-playback-bug` 分支（`a1f118c`）产出的 JSON 即属此类**，迁移脚本直接支持：

```json
{
  "schema": 1,
  "verified_true": [
    {
      "event_type": "collision",
      "frame_idx": 1600,
      "source_frame_idx": 1600,
      "box_tokens": ["Box_2010"],
      "confirmed_box_tokens": ["Box_2011"],
      "person_id": 0
    }
  ]
}
```

| 字段 | 迁移用途 |
|------|----------|
| `confirmed_box_tokens` | **写入 `bindings` 的唯一依据**（用户真实确认货框） |
| `box_tokens` | 不直接进入 binding；有 timeline 时写入 v2 帧级 `box_tokens`（检测框展示） |
| `person_id` | 写入对应 binding |
| `event_type: "frame"` | 普通帧；仅含 `confirmed_box_tokens` 时也可迁移 |

**检测框与确认框不一致（如 `Box_2010` 检测、`Box_2011` 确认）可以正确迁移**：binding 只保留 `Box_2011`，不会误并 `Box_2010`。单测见 `test_legacy_with_confirmed_does_not_use_other_box_tokens`。

迁移后 v2 示例（有 timeline 时）：

```json
{
  "frame_idx": 1600,
  "event_type": "collision",
  "box_tokens": ["Box_2010", "Box_2011"],
  "bindings": [
    { "confirmed_box_tokens": ["Box_2011"], "person_id": 0 }
  ]
}
```

### 8.3 迁移规则速查

| legacy 情况 | 结果 |
|-------------|------|
| 有 `confirmed_box_tokens` | ✅ 迁入 `bindings`（与 `box_tokens` 是否一致无关） |
| 无 `confirmed`，`box_tokens` **仅 1 个** | ✅ 视为旧版逐货框标真，该 box 作为 binding |
| 无 `confirmed`，`box_tokens` **多个** | ❌ **ambiguous**，该 legacy 条目跳过；同帧若最终无有效 binding → **整帧清除** |
| 同帧多条 legacy | ✅ 合并为 **一条** v2 帧记录，多个 `bindings` |
| 已是 schema 2 | ✅ 规范化后保留（不重复迁移破坏） |

### 8.8 常见误区

| 误区 | 事实 |
|------|------|
| 「迁移后条数变少 = 数据丢了」 | 同帧多条 legacy 合并为一条 v2；ambiguous 帧按设计清除 |
| 「有 box_tokens 就会标那个框」 | v2 只认 `bindings.confirmed_box_tokens`；`box_tokens` 是检测/展示 |
| 「fix 分支 JSON 不能迁」 | 可以；该分支写 schema 1 扁平行，正是脚本目标格式 |
